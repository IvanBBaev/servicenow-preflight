## Why vendored, not depended on

Tessera must not take a runtime dependency on the syncrona workspace (different
release cadence, different license posture for the eventual product). The store
package therefore carries private copies of exactly the modules it needs, with
their data-loss and security rationale comments preserved verbatim.

## The one systematic adaptation

Upstream modules read the `ConfigManager` and `Logger` module singletons (and
`process.env`) and are tested with `jest.unstable_mockModule`. The vendored
copies are **injectable factories** — configuration accessors, the logger, the
previous-manifest accessor, and the environment are all passed in — so the
ported `node:test` suites need no module mocking and two independent instances
can coexist in one process. Function bodies, names, and comments are otherwise
preserved as closely as the workspace TypeScript/ESLint rules allow.

Both functions have zero callers in the workspace; the code is not deleted and no test is added to pin behaviour nobody chose.                                                                                                                                                                                                                |

## Behaviour divergences — rulings of 2026-09-26 (review wave 7, W7b)

These change behaviour and supersede the matching 2026-09-23 "kept / deferred" rulings above
where they overlap. Each carries a `Delegated decision 2026-09-26 (W7b …)` comment in the code.

| Item                                                       | Ruling                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L6 — foreign lock with a future or unparseable `createdAt` | **Stale.** `describeCollaborationLockTimeAnomaly` flags a `createdAt` more than `COLLABORATION_LOCK_FUTURE_SKEW_MS` (5 min) ahead, or unparseable; such a lock is reclaimed on any host with a `TESSERA_LOCK_TIMESTAMP` warning. Trade-off: a foreign host whose clock runs >5 min fast can lose its lock.                                                                                                                            |
| L7 — release ignored a refused eviction                    | **Retry, then throw.** Release retries up to `COLLABORATION_LOCK_RELEASE_ATTEMPTS` (4); if our lock is still on disk it throws and keeps `heldLockOwner`, so a retried release can still remove it.                                                                                                                                                                                                                                   |
| L8 — non-array `result` read as "no more rows"             | **Fault.** `extractResult` throws `TableAPIPagingError` unless `result` is an array; applies to every call site (paging, `getScopeId`, discovery, fallbacks, `listAppsFromTableAPI`).                                                                                                                                                                                                                                                 |
| L9 — skippable statuses and broad catches                  | **Narrowed.** `isTableSkippableError` skips 403/404 only (400 now faults). Table discovery, `sys_db_object` / dictionary fallbacks and the hierarchy walk skip only 403/404 and rethrow the rest — this supersedes the 2026-09-23 "swallow every error" ruling. Offset paging fails on a sys_id seen twice; each `sys_idIN` fallback chunk is checked for unrequested, duplicate, excess and (without an appended query) missing ids. |

Residual (superseded by the wave 13 rulings below): the bulk-download `sys_idIN` chunking had no
completeness check, and the fixed-limit discovery / field / `listApps` reads were unpaged.

## Behaviour divergences — rulings of 2026-09-28 (wave 13)

These supersede the 2026-09-23 "Unpaginated dictionary / `sys_db_object` reads — deferred to a
re-vendor" row and the W7b residual above: the paging is hand-applied here rather than waiting for
a re-vendor. Each carries a `Delegated decision 2026-09-28 (wave 13): …` comment in the code.

| Item                                                                    | Ruling                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bulk download (`buildBulkDownloadFromTableAPI`) `sys_idIN` completeness | **Fail closed.** Every requested sys_id must come back exactly once. Unrequested, duplicate and excess rows fail the chunk; missing ids are collected across all chunks and fail the table with `SysIdCompletenessError` (exported; a `TableAPIPagingError` carrying `table` and `missingSysIds`, message names up to 20 ids). Not a skippable 403/404, so it propagates and fails the download.                                                                                             |
| `checkSysIdChunk` → `auditSysIdChunk`                                   | **Split.** The audit throws on unrequested / duplicate / excess rows and returns the missing ids; the manifest fallback still tolerates a short answer only under a `tableOptions.query`, and now names the missing ids (`SysIdCompletenessError`).                                                                                                                                                                                                                                          |
| `sys_idIN` chunking                                                     | **Length-bounded.** `chunkSysIds` caps each chunk at `SYS_ID_CHUNK_SIZE` (200) ids **and** `SYS_ID_QUERY_MAX_ENCODED_CHARS` (6000) characters of percent-encoded list (`%2C` separators counted), so a 32-char-id chunk holds 171 ids. Upstream's `chunkArray` (count only) is removed.                                                                                                                                                                                                      |
| Unlistable sys_ids                                                      | **Refused before any request.** `assertSysIdsListable` rejects an empty id or one containing `,`, `^` or whitespace, which would otherwise alter the `sys_idIN` query.                                                                                                                                                                                                                                                                                                                       |
| Fixed-limit discovery / field / `listApps` reads                        | **Paged with a total-row cap.** `sys_db_object` scope discovery and both dictionary discovery reads (`TABLE_DISCOVERY_MAX_ROWS` = 100 000), `getFileFieldsForTable` / `getTextFieldsForTable` (`DICTIONARY_FIELD_MAX_ROWS` = 20 000) and `listAppsFromTableAPI` (`LIST_APPS_MAX_ROWS` = 10 000) go through `tableAPIGetAllRows`, which gained an optional `maxRows`: exceeding it throws `TableAPIPagingError` ("exceeded the row cap"), never a truncation. Page sizes keep the old limits. |

Residual (not fixed): a record deleted (or hidden by an ACL) after the manifest was built fails the
bulk download until the manifest is rebuilt; `getScopeId` and the table-hierarchy lookup stay
single-row `limit 1` reads; the `sys_metadata` discovery pager has no row cap (only the 1000-page cap).
The last two are superseded by the wave 14 rulings below.

## Behaviour divergences — rulings of 2026-09-30 (wave 14)

These supersede the matching parts of the wave 13 residual above. Each carries a
`Delegated decision 2026-09-30 (wave 14): …` comment in the code.

| Item                                      | Ruling                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sys_metadata` reads without a row cap    | **Capped.** Whole-scope discovery (`getTableNamesInScope`) and the per-table sys_id fallback (`getScopeMetadataRowsForTable`) pass `SCOPE_METADATA_MAX_ROWS` (250 000, above `TABLE_DISCOVERY_MAX_ROWS` because sys_metadata holds every metadata record, not just tables) to `tableAPIGetAllRows`: exceeding it throws `TableAPIPagingError` ("row cap"), never a truncation, and discovery does not fall back. |
| `getScopeId` single-row `limit 1` read    | **Reads 2, refuses more than 1.** Two `sys_app` rows for one scope code are reported as a failed lookup (`ScopeLookup.kind === "failed"`, "ambiguous"), not a found or a missing scope; `limit 1` would have built against whichever row came first.                                                                                                                                                             |
| Table-hierarchy `sys_db_object` `limit 1` | **Reads 2, refuses more than 1.** Two rows for one `name=` query throw `TableAPIPagingError` (not a skippable 403/404), so the table lands in `failedTables` instead of silently following one of two parents.                                                                                                                                                                                                   |
| `tableAPIGetAllRows` total cross-check    | **Unchanged, now covered on more paths.** Still dormant until an `SNClient` adapter supplies `total`; tests pin a matching multi-page total, an over-count, a total that changes mid-read (the last report wins), and that a non-finite or non-number total is not cross-checked.                                                                                                                                |

Residual (not fixed): the table-hierarchy query interpolates the table name without
`escapeQueryValue` (names come from discovery or from the instance's own `super_class.name`); the
two-row read now fails closed if such a name ever widened the query to several rows.

**Wave 16 (2026-09-30).** Superseding the escaping above: every identifier `manifestBuilder.ts`
interpolates into an encoded query (scope code, scope sys_id, discovered and parent table names,
field-level excludes, bulk-download table keys) goes through `queryIdentifier`, an allowlist
(`[A-Za-z0-9_]`; sys_ids also `-`; field names also `.`) that throws `QueryIdentifierError`
before the read instead of escaping `^` into a literal that read as an empty table.
`escapeQueryValue` stays exported for free-text values. New module `src/snClientAdapter.ts`
(not vendored) adapts `@tessera/sn-client`'s single-page `queryTable`, injected as a function —
the store keeps zero runtime dependencies — and `createSnClientManifestBuilder` defaults
`requireTotalCount` to `true`, which makes the `tableAPIGetAllRows` total cross-check live for
that client.
